## What's new for a teacher

### One setup for a whole class, not five

**Dashboard → Add a body → Class with periods.** Enter the class name and how
many periods it meets; Tapin creates the parent class and every period body in
one step, instead of creating five bodies by hand and labeling each one. The
dashboard's body list now shows classes as collapsible groups — "English 11 ·
5 periods" — with a per-period breakdown table (meetings held, unique present,
average attendance %) on the class view.

### Switch periods from the scanner, not the dashboard

When the active body has sibling periods, the scanner now shows a period
switcher right on the check-in screen — no PIN, sibling-only, confirmed on
screen, and logged. It's disabled while a tap is being resolved, so a card
read mid-switch can never land in the wrong period. Teachers running an
unattended kiosk can turn on **Require PIN to switch periods** (off by
default) under the Teacher PIN card.

### Export any date range, not just "everything"

The old "Export all history" button is now **Export**, opening a dialog with
range presets (Today, Last 7 days, Past month, Past year, This school year,
All time, or a custom range). The workbook gains a **Summary** sheet (per
student: meetings attended, meetings held, attendance %, first/last check-in
in range) and a **By meeting** sheet (one row per session). The Activity sheet
is still included only for All time, matching prior behavior.

### Export a whole class across all its periods

When the active body has children, the Export dialog offers **This body
only** / **This body + all periods**. The subtree export adds a **Summary by
period** sheet and a **Period** column to Summary and Attendance, with a
"Total (each person counted once)" row that de-duplicates a student enrolled
in more than one period. Works for any parent/child body, not only classes —
a club with sub-teams gets the same rollup.

## Upgrading an installed Mac

Same in-place path as v1.0.1: teacher PIN → Dashboard → **Check for updates**
→ **Install and relaunch**. The app verifies the DMG's SHA-256 against the
published `.dmg.sha256` sidecar before it replaces anything. See
[docs/desktop-macos.md §9](../desktop-macos.md) and
[docs/plans/07-update-checker.md](../plans/07-update-checker.md).

## First install (Mac)

New to a device? Follow [docs/pilot-install.md](../pilot-install.md) end to
end — download, Gatekeeper, PIN, theme pack, first class.

## No data model changes

Design 09 reuses the existing parent/child body hierarchy (Design 08a) for
"class with periods" — there is no new entity and no Dexie schema bump. Export
range filtering reads existing `scannedAt`/`bodyId` fields on taps already in
the database. Upgrading in place does not touch the roster or attendance
history on the device.

## Known limitations carried forward

- Theme packs still ship **unsigned** for the pilot (D-T1) — ed25519
  verification is a later seam, not implemented here.
- 08c's *import* half (multi-body `.nfc-pack` import, Body Path column on
  import) is still deferred; only the export half shipped in Design 09 step 6.
- Only a macOS arm64 build is produced for this cut; no Intel or notarized
  build. See [docs/deferred-apple-developer.md](../deferred-apple-developer.md).
