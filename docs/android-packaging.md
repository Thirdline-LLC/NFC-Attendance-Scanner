# Packaging the scanner for Android

Capacitor wraps the same React bundle in a native shell. The APK carries every
asset, so **the installed app needs no website, no server and no internet
connection**.

The `android/` project is generated by Capacitor and **committed**. You do not
run `cap add android`.

Everything below through "Build a debug APK" has been run and verified. The
release-signing, device and kiosk sections need hardware or credentials and are
written from the documented behaviour — they are marked where that matters.

## Identity

```
applicationId   org.stjohnschs.attendance
app name        SJC Attendance
minSdk 24  ·  compileSdk 36  ·  targetSdk 36  ·  AGP 8.13.0  ·  Gradle 8.14.3
```

`org.stjohnschs.attendance` is a real, school-owned reverse-domain identifier
already shipping in `capacitor.config.ts`, `android/app/build.gradle`
(`applicationId` and `namespace`), `strings.xml` and the iOS project. **It is
not a placeholder and must not be changed.** Android identifies an update as
the same app by this string; changing it makes the Play/installer treat the new
build as a different app, and the existing install's roster and attendance
history become unreachable.

## 1. Install Android Studio and the SDK

Download from [developer.android.com/studio](https://developer.android.com/studio)
and run it once. On first launch its setup wizard installs the SDK, the
platform tools and an emulator image.

Then **Settings → Languages & Frameworks → Android SDK → SDK Platforms**, and
tick **Android 16 (API 36)** — `compileSdk`/`targetSdk` are 36. Under **SDK
Tools**, tick **Android SDK Build-Tools**, **Android SDK Platform-Tools** and
**Android SDK Command-line Tools**.

Tell your shell where it went:

```bash
# macOS  (~/.zshrc)
export ANDROID_HOME="$HOME/Library/Android/sdk"
# Linux  (~/.bashrc)
export ANDROID_HOME="$HOME/Android/Sdk"

export PATH="$PATH:$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin"
```

### Without Android Studio

Command-line only, which is how the verification for this document was done:

```bash
mkdir -p ~/Android/sdk/cmdline-tools && cd ~/Android/sdk/cmdline-tools
curl -O https://dl.google.com/android/repository/commandlinetools-linux-11076708_latest.zip
unzip commandlinetools-*.zip && mv cmdline-tools latest
export ANDROID_HOME=~/Android/sdk
yes | $ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager --licenses
$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager \
  "platform-tools" "platforms;android-36" "build-tools;36.0.0"
```

(Use the `commandlinetools-mac-*.zip` URL on macOS.)

### Pick the right JDK

**AGP 8.13 supports JDK 17 through 21. JDK 22 and newer will not work.**

```bash
java -version                 # check what you have
export JAVA_HOME=/path/to/jdk-21
```

Android Studio bundles a suitable JDK — **Settings → Build Tools → Gradle →
Gradle JDK**. From the command line, `brew install --cask temurin@21` or
[Adoptium](https://adoptium.net) gets you one.

## 2. Build the web bundle and sync it

```bash
pnpm --filter @workspace/nfc-attendance-scanner run native:sync
```

That is `build:native` (relative asset paths, no service worker, no manifest)
followed by `cap sync android`, which copies `dist/public` into
`android/app/src/main/assets/public` and refreshes the plugin list.

Verified output:

```
✔ Copying web assets from public to android/app/src/main/assets/public
✔ Creating capacitor.config.json in android/app/src/main/assets
[info] Found 2 Capacitor plugins for android:
       @capacitor/filesystem@8.1.3
       @capacitor/share@8.0.1
```

**Run this after every change to `src/`.** Gradle compiles the native shell; it
has no idea the web assets changed.

`capacitor.config.ts` deliberately has **no `server` key**. The bundle is
served from `webDir` at the app's own origin, `https://localhost`, which is
what keeps the kiosk working with no network at all. Adding `server.url` would
point a shipped app at a website. Do not.

## 3. Open the project

```bash
pnpm --filter @workspace/nfc-attendance-scanner run native:android
```

Syncs and opens `android/` in Android Studio. First open takes a few minutes
while Gradle downloads its dependencies.

## 4. Run it

### On an emulator

Android Studio → **Device Manager** → **Create Device** → a tablet profile
(Pixel Tablet is a good match for a front-desk device) → an API 34+ system
image → **Finish**. Then pick it in the device dropdown and press **Run ▶**.

An emulator has no USB HID reader. Type a UID into the app instead — the hidden
input takes keyboard input from anywhere. Use `04AA0000000001`.

### On a real tablet

1. **Settings → About tablet**, tap **Build number** seven times.
2. **Settings → System → Developer options**, turn on **USB debugging**.
3. Connect by USB and accept the "Allow USB debugging?" prompt on the tablet.
4. `adb devices` should list it. Pick it in Android Studio and press **Run ▶**.

## 5. Build a debug APK

```bash
pnpm --filter @workspace/nfc-attendance-scanner run android:apk
```

or, by hand:

```bash
cd artifacts/nfc-attendance-scanner/android
./gradlew assembleDebug
```

Output — **verified, 4.7 MB**:

```
artifacts/nfc-attendance-scanner/android/app/build/outputs/apk/debug/app-debug.apk
```

A debug APK is signed with the SDK's shared debug key. It installs and runs,
and is fine for testing. It is **not** for distribution: everybody's debug key
is the same one, so Android will refuse to upgrade a debug install to a release
build, and vice versa.

Verified contents of that APK: every asset bundled locally under
`assets/public/`, **no** `sw.js`, **no** `manifest.webmanifest`, and a
`capacitor.config.json` with no `server` key.

## 6. Build a release APK or AAB

### Create a keystore — outside the repository

```bash
keytool -genkey -v \
  -keystore ~/keys/sjc-attendance-release.jks \
  -alias sjc-attendance -keyalg RSA -keysize 4096 -validity 10000
```

**Where this file lives matters more than almost anything else here.**

- Keep it **outside the repository**. `.gitignore` blocks `*.jks`, `*.keystore`
  and friends, but that is a safety net, not the rule.
- Back it up somewhere that survives a laptop dying — a password manager with
  file attachments, or the school's IT safe.
- **Losing it is unrecoverable.** Android identifies an app by package name
  *and* signing key. Without the original key you cannot ship an update to
  anyone who already installed it; the only way out is a new package name,
  which is a new app, which loses everyone's data.
- Never paste the password into a chat, a source file, a commit, an issue or a
  CI log.

### Point Gradle at it, without writing the password down

Create `~/.gradle/gradle.properties` — in your home directory, **not** in the
project:

```properties
SJC_STORE_FILE=/Users/you/keys/sjc-attendance-release.jks
SJC_KEY_ALIAS=sjc-attendance
```

Then add to `android/app/build.gradle`, inside `android { }`:

```gradle
signingConfigs {
    release {
        storeFile file(project.findProperty("SJC_STORE_FILE") ?: "/dev/null")
        keyAlias project.findProperty("SJC_KEY_ALIAS")
        // Read from the environment so nothing is ever written to disk.
        storePassword System.getenv("SJC_STORE_PASSWORD")
        keyPassword   System.getenv("SJC_KEY_PASSWORD")
    }
}
buildTypes {
    release {
        signingConfig signingConfigs.release
        minifyEnabled false
        proguardFiles getDefaultProguardFile('proguard-android.txt'), 'proguard-rules.pro'
    }
}
```

This block is **not** in the repository — it is added by whoever holds the key,
on the machine that holds it. Then:

```bash
export SJC_STORE_PASSWORD=...   # typed into the shell, never committed
export SJC_KEY_PASSWORD=...

./gradlew assembleRelease   # → app/build/outputs/apk/release/app-release.apk
./gradlew bundleRelease     # → app/build/outputs/bundle/release/app-release.aab
```

**APK** is what you sideload. **AAB** is only for Google Play, which this
project does not use — build one only if that changes.

Bump `versionCode` (an integer, must increase every release) and `versionName`
in `android/app/build.gradle` before each release.

## 7. Install the APK without Google Play

Nothing here involves the Play Store.

**Straight over USB**, the easiest way:

```bash
adb install -r app-release.apk      # -r replaces an existing install, keeping its data
```

**By hand on the tablet:** copy the `.apk` to it (USB, Drive, email to
yourself), open it in **Files**, and approve **Install unknown apps** for
whichever app you opened it from when Android asks. Android 8+ asks per-app
rather than with one global switch.

**Through an MDM** — Intune, Mosyle, Jamf, Google Workspace: upload the APK as
a line-of-business / private app and push it. This is the right answer for a
school with more than one tablet.

⚠️ **`adb install -r` keeps the app's data; `adb uninstall` then install does
not.** Debug and release builds are signed with different keys and cannot
replace one another — uninstall first, and export the attendance beforehand.

## 8. Lock the tablet to the app

### Screen pinning — free, built in, good enough for one tablet

**Settings → Security → More security settings → App pinning** → on, and turn
on **Ask for PIN before unpinning**.

To pin: open the scanner, swipe up and hold for the recent-apps view, tap the
app's icon, **Pin**. To unpin, hold Back and Overview together, then enter the
PIN.

A student cannot leave the app without the PIN. A determined one with a
keyboard still can, so it is a deterrent rather than a lock.

### Managed kiosk mode — for a real deployment

Enrol the tablet in an MDM (Mosyle, Jamf School, Intune, or Google's Android
Enterprise) as a **fully managed dedicated device**, and set the scanner as the
**lock-task / kiosk app**. That gives you a device that boots into this app,
cannot leave it, and has no other apps at all.

Your MDM needs the release APK and the package name
`org.stjohnschs.attendance`.

## 9. The reader

### Hardware

The ACS reader is a **USB HID keyboard-wedge**: the tablet sees a keyboard, and
a tap types fourteen uppercase hex characters and Enter. **The app uses no
Android NFC API and requests no NFC permission** — the tablet's own NFC radio,
if it has one, is not involved.

Plug it in with a **USB-C OTG adapter**. If the reader is not recognised, or
the tablet warns about power, use a **powered USB-C hub** — a tablet's port
supplies limited current and a bus-powered reader can sit right at the edge of
it. A powered hub also lets the tablet charge while the reader is connected,
which matters for an hour-long meeting.

### Test it

1. Open any text field on the tablet — a notes app is ideal.
2. Tap a card.
3. You must see **exactly fourteen uppercase hex characters** (`0-9`, `A-F`)
   and then a newline, from the Enter.

If you see lowercase, a different length, or extra characters, the reader is
configured for a different output format. Fix it with the vendor's
configuration tool before going near the app: `src/lib/scan-format.ts` validates
`^[0-9A-F]{14}$` and will report anything else as an invalid scan.

Then in the app: **Enroll** mode, tap a card, fill in the student, save. Switch
to **Check-in** and tap the same card — the count goes up. Tap it again — it
reports a duplicate and the count does not move.

> **Not verified.** Nobody has run this build against the physical ACS reader on
> the physical tablet. The reader contract (14 uppercase hex + Enter) is what
> the app validates and what the existing tests cover, but "the reader works
> with this APK" is a claim only a device can support. Do the test above before
> a first real meeting.
